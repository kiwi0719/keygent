# Weaver 提示缓存设计

草案 v1 · 2026-10-01

## 一、缓存怎么省钱

每轮请求都把整段对话重发一遍。服务端会记住“上次发过的开头”，这次开头一样的部分就不用重算，按一到两折计费。

```
第 1 轮: [工具][system][问题]
第 2 轮: [工具][system][问题][回复][工具结果]                 ← 前一段命中
第 3 轮: [工具][system][问题][回复][工具结果][回复][工具结果]   ← 前一段命中
```

**开头只要变了一个字节，从那里往后全部失效。** 所以缓存的核心不是“怎么开”，而是“前缀不能变”。

## 二、铁律：前缀不变

对同一本账本，第 N 次调模型发出去的请求，必须是第 N+1 次请求的逐字节前缀（缓存标记本身除外，它每轮会往后挪）。

以后加任何功能都要守住这条。已知会破坏它的做法：

| 做法 | 规矩 |
|---|---|
| system 里放时间、目录、git 状态等会变的东西 | 不放。要放就作为消息追加，或放在缓存断点之后 |
| 工具列表顺序或描述变化 | 顺序固定；会话中途不增删工具 |
| JSON 序列化不稳定 | 工具参数用 `raw_args` 原样回传；字段顺序固定 |
| 改写历史（压缩、裁剪） | 会让缓存失效，只在值得时做（以后的压缩设计要算这笔账） |
| 换模型、换协议 | 必然失效，接受 |

这条铁律有一个专门的测试（见第六节）。

## 三、各家怎么开启

| 服务 | 方式 | 我们做什么 |
|---|---|---|
| OpenAI、DeepSeek、Kimi、Gemini 等 | 自动：前缀相同就命中 | 只需保证前缀稳定 |
| OpenAI 官方 | 自动；可传 `prompt_cache_key` 让同一会话落到同一批机器 | 用会话 id 当 key |
| Anthropic 原生 | 在内容块上标 `cache_control`，最多 4 个断点 | 标断点 |
| OpenRouter 上的 Claude（OpenAI 格式） | 在内容片段上带 `cache_control` | 标断点，格式不同 |

共同限制：请求要达到最小长度（一般 1024 token）才会缓存。Anthropic 缓存默认 5 分钟过期，写入比普通输入贵约 25%，读取约一折。

## 四、放在哪一层

内核和账本都不知道缓存。分两块：

**1. 缓存策略**（`weaver/cache.py`）：在 `project` 输出的消息上加标记。只标一处：**最后一条消息**加 `cache: true`。这个断点每轮往后挪；Anthropic 会往前找到上次的断点位置并命中。

**2. 适配器翻译**：

| 适配器 | 工具定义 | system | 带 `cache: true` 的消息 |
|---|---|---|---|
| Anthropic | 最后一个工具加 `cache_control` | 改成文字块并加 `cache_control` | 最后一个内容块加 `cache_control` |
| OpenAI 格式 + 需要显式标记的模型 | — | 改成文字片段并加 `cache_control` | 最后一个文字片段加 `cache_control` |
| OpenAI 官方 | 请求里加 `prompt_cache_key` = 会话 id | | |
| 其他 | 忽略 | | |

一共最多 3 个断点，在 Anthropic 4 个的上限内。

“需要显式标记的模型”由方言设置 `cache_marks` 决定：`never`（默认）/ `always` / `claude`（模型名里含 claude 才标，openrouter 预设用这个）。可用 `WEAVER_CACHE_MARKS` 覆盖。

## 五、观测

每轮显示读了多少缓存、写了多少缓存。如果上一轮已经有缓存，这一轮命中数却明显下降，就提示“缓存可能被打断”，说明前缀在某处变了。（超过 5 分钟没请求导致过期，也会触发这个提示。）

## 六、测试

1. **前缀不变**：用假模型跑一个多轮带工具的任务，记下每次调模型时发出的请求体。去掉缓存标记后，第 N 次的消息列表必须是第 N+1 次的前缀，工具和 system 完全相同。两种协议各测一次。
2. **断点位置**：Anthropic 请求里 `cache_control` 恰好出现在最后一个工具、system、最后一条消息的最后一个块上，总数不超过 4。
3. **OpenAI 格式**：`cache_marks=claude` 时只对 claude 模型加标记；OpenAI 官方带 `prompt_cache_key`。
4. **观测**：命中数下降时给出提示。
5. **真实验证**（手动）：发一个超过 1024 token 的多轮任务，第二轮起 `cached > 0`。

## 七、暂不做

1 小时缓存（`ttl: 1h`）、按 token 数估算“要不要打断点”、压缩与缓存的联动（留给压缩设计）。

## 进度（2026-10-01）

已实现：`weaver/cache.py`（断点标记、打断检测）、两个适配器的翻译、CLI 显示 `cached` / `write` 并在命中骤降时提示。测试见 `tests/test_cache.py`（前缀不变测试已用“每轮改 system”的变异验证过能抓到问题）。

真实验证（OpenRouter，claude-sonnet-4.5，读两段文件的三轮任务）：

| 协议 | 第 2 轮 | 第 3 轮 |
|---|---|---|
| OpenAI 格式（`cache_marks=claude`） | in=3893 cached=0 | in=6795 **cached=3887** |
| Anthropic 格式 | in=3893 cached=0 write=3887 | in=6795 **cached=3887** write=2902 |

第 1 轮 970 token，低于最小缓存长度，所以没有写入。

已知例外：DeepSeek / Kimi 预设的 `echo_reasoning_scope=turn` 会在新一轮用户消息后去掉旧回复里的 `reasoning_content`，这会改变前缀。这是按这两家的回传要求做的取舍（未验证），它们的服务端本身也不要求旧思考过程。
