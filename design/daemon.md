# Weaver 常驻服务（weaverd）设计 · 阶段 A

草案 v1 · 2026-10-01

## 一、目标

把 Weaver 从“问一句、做完就退出”的命令行，变成**常驻在 Mac 上的后台服务**：交代一件事（可以很长），它在后台做；要你放行、卡住、做完了都告诉你；你随时可以从 Keygent（SwiftUI 菜单栏 App）或命令行看进度、插话、放行。

范围（用户已定）：先跑在自己的 Mac 上；前端是 Keygent（已经在做，目前是假数据）；主动能力第一版只要“长任务委派”，定时、webhook 以后再说。

## 二、Keygent 需要什么（从它的界面倒推）

| Keygent | 后端提供 |
|---|---|
| ① 启动器：一句话 + 附件（文件、剪贴板） | 新建任务；附件先上传成 blob 引用，作为输入片段（内核本来就支持 image / file 片段） |
| 任务列表：`wait / run / done / error` + 一行状态 + 时间 | 任务列表，每个任务的状态从账本推出来 |
| ② 胶囊：空闲 / 在跑（几个）/ 等你（哪件，还有几件）/ 出错 | 一个汇总接口 + 状态变化时推送 |
| ③ 任务窗口的放行区（`Gate`：标题、说明、放行 / 先等等） | 内核的“等待”（审批、卡住了问人），附上人能读的说明 |
| ③ 过程（`ProcStep`：你 / Agent / 步骤，步骤有工具、输出、理由） | 把账本翻译成人能读的步骤列表 |
| ④ 等你的事：所有任务里等你的，逐个看、放行 / 不行 / **改一下再放行** / 回答问题 | 全局的“等待队列”；新增“改参数后放行” |
| ⑤ 详情：时间线 | 同一份步骤列表 |

## 三、整体结构

```
Keygent（Swift） ─┐
weaver（命令行）──┼── HTTP（127.0.0.1，带 token） ──▶ weaverd
以后：手机 / IM ──┘        + SSE 事件流                 ├─ 任务管理：每个任务一本账本、一个工作线程
                                                         ├─ 内核（不变）+ 执行者（同现在）
                                                         ├─ 后台任务登记表、MCP 连接、记忆、skills
                                                         └─ 通知（App 没开时用系统通知兜底）
```

**内核不变**：账本、`fold`、`decide`、等待、背景信息、通知都是现成的。weaverd 只是换了一种“谁来调用执行者、事件发给谁”。

## 四、任务（= 会话）

- 一个任务就是一个会话：一本账本 + 元信息（标题、工作目录、创建时间、来源）。
- 存在 `~/.weaver/tasks/<任务 id>/`：`ledger.jsonl`（账本）、`meta.json`（元信息）、`blobs/`、`jobs/`、`outputs/`。
  和命令行模式的 `<项目>/.weaver/` 分开：常驻服务管理的任务可能跨多个项目。
- **工作目录**：新建任务时指定（Keygent 的文件选择器 / 命令行当前目录）；不指定就用 `~/Weaver/scratch/<任务 id>`（一个空目录，避免默认在家目录乱写）。沙箱、文件工具都以它为根。
- **标题**：先用用户这句话的前 20 个字；第一次模型回复后，让模型顺手起一个短标题（一次很小的调用）。

### 状态（给列表和胶囊用）

从账本推出来，不另存：

| 状态 | 条件 | Keygent |
|---|---|---|
| `running` | 有进行中的任务、没有在等的事 | run（绿） |
| `waiting` | 有没解决的等待（审批、卡住了问人、输入待确认） | wait（琥珀），进“等你的事” |
| `done` | 最近一个任务结束，状态 done | done |
| `cancelled` | 最近一轮被取消 | 灰色（“已取消”） |
| `error` | 结束状态是 error / stuck / budget / refusal / truncated | error（红），并附一句说明（见下） |
| `queued` | 任务管理器还没轮到它（同时在跑的已满） | 灰色（“排队中”）；这个账本里推不出来，由任务管理器标 |
| `idle` | 还没开始 | — |

`error` 的说明（`note`）：budget →“预算用完，已收尾”（收尾的答案照样显示）；stuck →“卡住了，已停下”；refusal →“模型拒绝了这个请求”；truncated →“输出被截断”；error → 失败原因的第一行。

（2026-10-01 与用户确认：取消显示为“已取消”而不是出错；预算用完算出错但附说明，因为收尾答案是不完整的。）

每个任务还给一行“现在在干什么”（`now`）：在跑就是最近一个工具调用的摘要（“读 calc.py”“跑测试”）；在等就是等什么；结束了就是结论的第一行。

## 五、工作线程与并发

- 每个任务一个工作线程，平时睡着；有事（新输入、放行、取消、后台任务结束）就醒来跑执行者的 `run()`，跑到“没事可做或要等”就继续睡。
- **同时最多跑 4 个任务**（`WEAVER_MAX_RUNNING`），多的排队，状态显示“排队中”。
- 同一个任务同一时刻只有一个工作线程写账本（单写者，账本存储已有序号校验兜底）。
- **执行者里交互的地方全部改成“等待”**：常驻服务里没有终端可以 `input()`，审批、卡住了问人、项目级 skill / MCP 的信任确认，都变成账本里的等待，经接口由客户端回答。

### 任务管理器怎么做（第 2 步细化，2026-10-01）

**不是每个任务一直占一个线程**，而是一个容量为 4 的线程池加每个任务三个标记：

- `wake(任务)`：有事了（新建、插话、放行、取消、启动时恢复）就叫一下。
  - 它正在跑或在排队：只记一笔“跑完再看一眼”（dirty），不重复排队。
  - 否则：放进线程池排队，状态显示“排队中”。
- 轮到它：反复“清掉 dirty → 跑执行者 `run()`”，直到跑完时没人再叫过它，就放手（睡着）。
  `run()` 停下的原因只有两种：没事可做了，或者在等人。不用自己判断，内核说了算。
- 这样“醒来 / 睡着”不需要条件变量；不跑的任务不占线程，几百个任务也只有 4 个线程。

**谁写账本**：每个任务一个执行者（Runner）实例，常驻内存。接口线程的插话、放行、取消，和工作线程的执行，都通过同一个实例写，执行者里已有的锁保证同一时刻只有一个写者。
账本存储（`JsonlEventStore`）的增量读取原来不防多线程：一个线程在读、另一个在追加，可能把同一条记录读进来两次。加一把锁。

**取消什么时候生效**：取消是往账本里记一笔，内核在当前这一步做完后看到它就收尾。正在跑的长命令要等它跑完（或超时）；“立刻打断正在跑的命令”放到第 5 步，和后台任务登记表一起做。

**回答等待**：接口给的是 `decision`（见 api.md），任务管理器翻译成内核认的值：

| decision | 记进账本的值 |
|---|---|
| allow / continue | `{"allow": true}` |
| deny / stop | `{"allow": false, "note": 理由}` |
| always | `{"allow": true, "always": 命令前缀或 MCP 工具名}`（和命令行的 a 一样） |
| hint | `{"allow": true, "note": 提示}` |
| allow + args | 第 4 步之前**直接报错**，不能悄悄按原参数执行 |

`decision` 不在这件等待的 `choices` 里 → 报错；已经被回答过 / 作废了 → 冲突（409）。

**执行者出了没接住的异常**（代码 bug）：记一笔这一轮结束、状态 error、原因“服务内部出错：…”，任务不会卡在“在跑”。

**归档**：没在跑就直接移走；在跑就先取消，等它这一轮停下后再移走。

**启动时恢复**：扫一遍没归档的任务，`fold` 账本，有进行中的一轮或没处理的输入就 `wake`；在等的继续等。

**交互的地方**：执行者不给 approver，等待自然就停在账本里；`interactive=True`，卡住了走“问人”。项目级 skill 的信任确认：第一版只加载已经信任过的（在命令行里确认过一次即可），未信任的跳过；MCP 第一版不接，放到第 5 步（MCP 连接要在任务之间共享）。

**对外通知**：任务管理器只往外发三种消息：账本事件、流式片段、任务摘要变了（状态 / now / 在等几件 / 排队）。翻译成 api.md 的 `step` / `wait` / `task` 事件是第 3 步的事。

**造执行者的工厂可以换**：测试用假模型，真跑用 `weaver/daemon/factory.py`（照命令行的搭法，但所有路径都以任务的工作目录为根，不依赖进程的当前目录）。

## 六、接口（HTTP + SSE）

> 完整字段和 JSON 示例以 [api.md](api.md) 为准（给 Keygent 的接口说明）。和下面相比，api.md 定稿时做了这些调整：事件流不直接推账本事件，改推翻译好的 `step`；新增 `wait_closed`、`archived`、`reset`、`ping` 事件；新增 `PATCH /v1/tasks/{id}` 改标题；`/v1/status` 带出 `first_wait` 和 `error`。

只监听 `127.0.0.1`；每个请求带 `Authorization: Bearer <token>`。端口和 token 写在 `~/.weaver/daemon.json`（权限 0600），客户端从这里读。用标准库 `ThreadingHTTPServer`，不加依赖。

### 1. 任务

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/v1/tasks` | 列表：id、标题、状态、`now`、更新时间、在等几件 |
| POST | `/v1/tasks` | 新建并开跑：`{text, workdir?, attachments?: [blob 引用]}` |
| GET | `/v1/tasks/{id}` | 详情：元信息、状态、步骤列表（第七节）、在等的事、最终结论 |
| POST | `/v1/tasks/{id}/input` | 插话 / 追问：`{text, attachments?}`（任务结束了就开启新一轮） |
| POST | `/v1/tasks/{id}/cancel` | 取消当前这一轮 |
| DELETE | `/v1/tasks/{id}` | 归档（移到 `~/.weaver/tasks/.archive/`，不真删；它的后台任务一起结束） |

### 2. 等你的事

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/v1/waits` | 所有任务里没解决的等待，按时间排：任务、类型（审批 / 卡住 / 输入确认）、标题、说明、能做的选择 |
| POST | `/v1/waits/{wait_id}` | 回答：`{decision: "allow" / "deny" / "always", args?, note?}` |

**改一下再放行**（Keygent ④ 的“改”）：`{decision: "allow", args: {改过的参数}}`。内核规则 6 遇到带 `args` 的放行，就用改过的参数执行，并在工具结果开头注明“用户把参数改成了：…”，让模型知道。这是内核唯一的改动。

### 3. 汇总、附件

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/v1/status` | 胶囊用：在跑几个、在等几件（第一件是哪个任务）、有没有出错的 |
| POST | `/v1/blobs` | 上传附件（文件内容），返回 blob 引用 |

### 4. 事件流（SSE）

`GET /v1/events?after=<游标>`：所有任务的事件合在一条流里。

```
event: ledger        账本事件（持久的）：{task, seq, cursor, event}
event: delta         流式片段（可以丢）：{task, delta}
event: task          任务状态变了：{task, status, now, waiting}（客户端据此刷新列表和胶囊）
event: wait          出现新的等待：{task, wait}（客户端可以弹通知）
```

- **断线重连**：每条持久事件带一个全局递增的 `cursor`；客户端记住最后收到的，重连时 `?after=` 补齐（OpenHands 的做法）。`delta` 不补，丢了无妨，完整内容随账本事件到。
- **慢客户端**：每个连接一个有上限的队列，满了就断开它，让它重连补齐（OpenHands 的做法），不拖慢服务。

客户端的做法：启动时 `GET /v1/tasks`、`GET /v1/waits` 拿全量；之后订阅事件流，收到 `task` / `wait` 就局部刷新，打开某个任务时 `GET /v1/tasks/{id}`。

### 接口层怎么做（第 3 步细化，2026-10-01）

**事件总线**（`weaver/daemon/events.py`）：接在任务管理器的通知上，翻译成 api.md 的事件。

- `step`：账本有新事件时，重新翻译这个任务的步骤，和上次的比，新增的和变了的发出去（按下标比，步骤只会追加或原地更新）。
- `wait` / `wait_closed`：任务摘要变化时，比较这个任务“在等的事”的 id 集合，多出来的发 `wait`，少了的发 `wait_closed`。不用分别处理“回答了”“取消作废了”“归档了”几种情况。
- `task`、`archived` 原样转；`delta` 不带游标。
- 游标：全局递增的整数。最近 1 万条放在内存里的环形缓冲区；重启后游标从 0 重来，客户端带着旧游标来，比缓冲区里最新的还大 → 也发 `reset`。
- 每个连接一个最多 1000 条的队列；满了就把它标成“断开”，它的写线程退出，客户端重连补齐。
- 订阅和补发的衔接：先登记队列、再拷缓冲区，然后按游标去重，保证不漏不重。

**HTTP**（`weaver/daemon/server.py`）：标准库 `ThreadingHTTPServer`，每个请求一个线程（SSE 连接也是，一直挂着）。

- 只绑 `127.0.0.1`；token 用 `secrets.token_urlsafe`，比较用 `hmac.compare_digest`；`daemon.json` 先建成 0600 再写。
- 端口默认 0（系统分配），实际端口写进 `daemon.json`。
- 不认识的路径 404，方法不对 405，JSON 解析失败 400，请求体上限：JSON 1 MB、附件 50 MB。

**附件**：`POST /v1/blobs` 存进 `~/.weaver/blobs`（按内容哈希），另记一份 `uploads/<id>.json`（名字、类型、大小、哈希）。新建任务 / 插话带上附件时：

- 附件**复制进任务的工作目录** `附件/<文件名>`，并在输入里写一句“附件已放在 附件/客户名单.xlsx”：Excel、Word 这类模型不能直接看的，Agent 可以用工具去读。
- 图片、PDF、文本另外作为输入片段直接给模型看（内核和模型适配器本来就支持）。

**已读**：打开任务详情（`GET /v1/tasks/{id}`）时记下“看过的时间”（元信息里的 `seen`）。胶囊的 `error` 只算“出错、且出错之后没看过”的任务。

**启动**：`python -m weaver.daemon`（第 6 步再包成 `weaver daemon start` 和 launchd）。启动时恢复任务，退出（Ctrl+C / SIGTERM）时删掉 `daemon.json`。

### 改参数后放行（第 4 步细化，2026-10-01）

用户在放行区把参数改了再放行，比如把 `npm publish` 改成 `npm publish --dry-run`。

- **记账**：`WaitResolved` 的值是 `{"allow": true, "args": {改过的参数}}`。账本里模型原来的那次调用不动（它说了什么就是什么）。
- **内核**（规则 6）：遇到带 `args` 的放行，用改过的参数执行，并把原参数记在 `edited_from` 里。改过的参数**再过一遍权限规则**：如果规则直接拒绝（比如改成了 `rm -rf /`），照样不执行。人放行只代替“问人”这一步，不代替硬拦截。
- **执行者**：工具结果开头加一句“[用户把参数改成了：{…}]”。模型看到的还是它自己发出的调用，靠这句话知道实际跑的是什么。
- **步骤**：标题按改过的参数显示，后面加“（你改过参数）”。
- **接口**：`args` 必须是对象，而且这件等待的 `choices` 里要有 `edit`；改参数只能配 `allow`。

### 后台命令与取消（第 5 步细化，2026-10-01）

在 round2.md 第三节“后台任务”的基础上落到常驻服务里。这一步只做后台 shell 命令，后台子 Agent 以后再做。

**后台命令**（`weaver/jobs.py`，`Jobs` 登记表，每个任务一个）：

- `bash(command, background=true)`：权限、沙箱、去密钥环境变量都和前台一样。输出**直接写文件** `<任务目录>/jobs/<id>.log`，不走管道，免得管道满了进程卡住。最多等 3 秒，把这 3 秒的输出和任务 id 一起返回。
- `job_output(id)`：读上次之后的新输出（脱敏、最多 30KB）。`job_kill(id)`：结束它，连同子进程。`jobs()`：列出全部后台命令。这三个工具放行，不问人：只能操作本任务自己启动的。
- **结束通知**：一个回收线程每秒看一次。后台命令结束（自己退出、被杀、闲置太久）时，往这个任务记一条 `system` 输入：“后台命令 X（npm test）结束了，退出码 1，最后几行输出：…”。任务还在跑，就当插话；已经结束，就开启新的一轮，Agent 被叫醒来处理结果。用户主动 `job_kill` 的不通知。
- **生命周期**：任务归档、weaverd 停止时一起结束；连续 24 小时没有新输出的自动结束（“保留”类的开发服务器）。
- **日志上限** 10 MB，超过只保留后一半。
- **登记 PID**：`<任务目录>/jobs/registry.json` 记 PID、进程组、命令、状态。weaverd 被强杀后重启时，找出上次还标着“在跑”的：确认那个 PID 还是我们启动的那个进程组的组长，而且命令对得上，才结束它（防止 PID 被系统复用后误杀别的进程），然后标成 `killed`（“weaverd 重启时清理”）。macOS 没有“父进程死了子进程跟着死”的机制，只能靠登记。
- 命令行模式也能用后台命令，Weaver 退出时一起结束。

**取消能打断正在跑的命令**：工具箱记住正在跑的前台命令（进程组）。执行者收到取消时，除了记一笔 `Cancelled`，再叫工具箱把这些进程组杀掉（先 TERM，2 秒后 KILL）。命令返回“被取消终止”，执行者回到内核，内核看到取消就收尾。正在等的模型请求不打断：最多等这一次回复回来，回来后内核看到取消，不会再执行它要的工具。

**recall**（round2.md 第一节，只做第一版）：`recall(query)` 搜当前任务的账本，包括被压缩掉的部分；`recall(seq=N)` 取某一条的原文。裁剪后的占位符带上序号：“[旧工具结果已清理（#123），需要时重新读取，或用 recall(seq=123) 取回原文]”。只读，放行。跨会话搜索以后再做。

### 薄客户端、launchd、系统通知（第 6 步细化，2026-10-01）

**命令行变成薄客户端**（`weaver/daemon/client.py`）：

- `weaver "……"`：weaverd 在运行（`daemon.json` 在、`/v1/status` 通），就交给它：新建任务（工作目录 = 当前目录）、订阅事件流、在终端里显示。weaverd 没运行，或者带了 `--local`、`-s`、`--compact`、`--undo`、`--log`、`--list`，就和以前一样本地直接跑。
- 显示：你的话、Agent 的话、每个步骤（标题，完成后一行输出摘要），和本地模式的风格一致。
- 要你放行时，直接在终端里问：`[y] 放行 [n] 拒绝 [a] 总是允许 [e] 改参数`。改参数时，`bash` 让你重新输入命令，其它工具让你输入 JSON。卡住时：`[c] 继续 [s] 停下`，或者直接输一句提示。
- **Ctrl+C 只是“不看了”**，任务在后台继续，提示 `weaver attach <id>` 接着看；要取消用 `weaver cancel <id>`。
- 子命令：`weaver tasks`、`weaver waits`、`weaver attach <id>`（先补显示已有的步骤，再接着看）、`weaver approve <wait_id> [allow|deny|always]`、`weaver cancel <id>`、`weaver archive <id>`。任务 id 可以只写前几位，只要唯一。
- 命令行连事件流时带 `X-Weaver-Client: cli` 头，见下面“系统通知”。
- 实现：读事件流的线程把事件放进队列，主线程逐个处理；遇到等待就在主线程里 `input()` 问人，期间来的事件先排着。

**launchd**（`weaver daemon …`）：

- `install`：写 `~/Library/LaunchAgents/ai.weaver.daemon.plist`，然后 `launchctl bootstrap gui/<uid>` 加载。设置为登录后启动（`RunAtLoad`）、异常退出后自动拉起（`KeepAlive` 里 `SuccessfulExit=false`：正常退出不拉起，所以 `stop` 才停得住）。程序是当前这个 Python 加 `-m weaver.daemon`，`PYTHONPATH` 指向项目目录，`--env` 指向安装时项目里的 `.env`（没有就用 `~/.weaver/.env`）。标准输出和错误写进 `~/.weaver/daemon.out`。
- `uninstall`：`launchctl bootout`，删掉 plist。
- `start`：装了 launchd 就 `launchctl kickstart`；没装就在后台起一个独立进程（`start_new_session`，输出写 `daemon.out`）。等 `daemon.json` 出现、`/v1/status` 通了才算启动成功。
- `stop`：给 `daemon.json` 里的 pid 发 SIGTERM，等它退出（weaverd 收到 SIGTERM 会正常退出，退出码 0，launchd 不会拉起）。
- `status`：在不在跑、端口、pid、在跑 / 在等 / 出错各几个、launchd 装没装。`logs`：看 `daemon.log` 最后 50 行。
- `daemon.json` 在、但对应的进程已经不在（被强杀），当作没在运行，启动时覆盖。

**系统通知**（`weaver/daemon/notify.py`）：

- 时机：出现新的等待（“Q3 流失分析 · 等你放行：跑命令 …”）、任务出错（带说明）、**跑了 1 分钟以上的任务**完成（短任务你多半就在看着，不打扰）。
- **Keygent 开着就不发**，由它自己提醒，免得一件事响两次。判断方法：有没有连着事件流、又不是命令行的客户端。命令行连事件流时带 `X-Weaver-Client: cli`，不算。
- 用 `osascript -e 'display notification …'` 发，放在后台线程，不阻塞。文字里的引号、反斜杠要转义。`--quiet` 可以关掉。
- 同一件事只发一次：等待按 id 去重；出错、完成按“状态变化”触发。

## 七、步骤列表：把账本翻译成人能读的

对应 Keygent 的 `ProcStep`：

| 账本 | 步骤 |
|---|---|
| 用户输入 | `you`：原话 |
| 模型回复里的文字 | `agent`：原话 |
| 工具调用 + 结果 | `step`：标题（人能读的一句话，如“读 calc.py 第 1–40 行”“搜索 \"def main\"”“跑命令 npm test”“派子 Agent：查错误处理”）、工具名、输出摘要（前 300 字）、理由（这次调用之前模型说的那段话） |
| 压缩、记忆提取、后台任务完成 | `step`，标题如“上下文压缩”“记住了 2 条”“后台任务 npm run dev 结束” |
| 等待 | 不进步骤，单独放在“在等的事” |

每种工具一个“标题模板”（`weaver/daemon/humanize.py`），不认识的工具就用“调用 工具名”。

## 七点五、通知

- Keygent 开着时：它收到 `wait` / `task` 事件自己决定怎么提醒（胶囊变色、系统通知）。
- Keygent 没开时：weaverd 用 macOS 系统通知兜底（`osascript -e 'display notification …'`），只在“需要你”（新的等待、出错、卡住）和“长任务做完”时发；`--quiet` 可以关。

## 八、长任务委派要的几处调整

- **规则**：常驻服务里 `interactive=True`（有客户端能回答），卡住了走“暂停问人”；审批照常进“等你的事”。
- **每个任务的预算**：默认 100 万 token（折算后）、200 步；在新建任务时可以调。
- **后台 shell 任务归 weaverd 管**：客户端断开不影响；任务归档或 weaverd 停止时一起结束；“保留”类的（开发服务器）闲置 24 小时自动结束；登记表记 PID，weaverd 崩溃重启后找回或清理。
- **记忆提取**：任务结束后在后台跑（这里是真的后台，不用等）。

## 九、生命周期

- `weaver daemon install`：写一个 launchd 配置（`~/Library/LaunchAgents/ai.weaver.daemon.plist`），登录后自动启动、崩溃后自动重启。`uninstall` 反过来。
- `weaver daemon start / stop / status / logs`：手动控制和查看。
- **启动时恢复**：扫描所有没归档的任务，`fold` 账本；有进行中的一轮就交给工作线程接着跑（内核的崩溃恢复规则现成：中断的模型调用重做、中断的工具调用补“执行中断”）；在等的继续等。
- 日志写 `~/.weaver/daemon.log`（按大小轮转）。

## 十、命令行变成薄客户端

- weaverd 在运行时，`weaver "……"` 就交给它：新建任务、订阅事件流、在终端里显示（和现在一样的显示），Ctrl+C 只是“不看了”，任务照样在后台跑（`weaver attach <id>` 接着看）；`weaver tasks`、`weaver waits`、`weaver approve <wait> [y/n/a]`。
- weaverd 没运行时，和现在一样本地直接跑（保留，方便调试和测试）。

## 十一、安全

- 只监听本机回环地址；token 必须带，`daemon.json` 权限 0600。
- 不开 CORS（浏览器网页拿不到 token）。

**压测找出来的问题（都是并发才会出现，单测没覆盖到）**：

1. **丢失唤醒**：工作线程决定“不用再看了”之后、真正把自己移出“在跑”名单之前，有一小段空档；这期间的放行只记了“跑完再看一眼”，却没人再看 → 任务永远停在“在跑”。修法：移出名单时（同一把锁里）再看一眼，有就重新排队。另加了一个能稳定复现的测试（在工作线程收尾发通知的那一刻放行），确认旧代码会失败。
2. **归档和其它操作交错**：插话拿到了已归档任务的执行者，往已经移走的目录里写，或者唤醒一个不存在的任务。修法：同一个任务的操作（插话、放行、取消、归档、改名、记已读）排队做；归档后的操作一律“没有这个任务”。
3. **读的同时被归档**：先看目录在、再打开文件时已经被移走 → 500。修法：读账本、读修改时间时接住“文件不存在”，当作空的。

### 第 5 步：后台命令、取消打断、recall（2026-10-01，已完成）

- `weaver/jobs.py`：后台命令登记表（每个任务一个，日志和 `registry.json` 在任务目录的 `jobs/` 下；命令行模式在 `.weaver/jobs/`）。`bash(background=true)`、`job_output`、`job_kill`、`jobs`。结束时通知，任务被叫醒；24 小时没有新输出自动结束；日志上限 10 MB；归档、weaverd 停止、命令行退出时一起结束；重启时按登记清理上次残留的。
- 取消：`ToolBox.running` 记着正在跑的前台命令，`Runner.cancel` 时整组结束，结果注明“任务被取消，命令被终止”，步骤显示“已取消”。weaverd 停止时也先结束正在跑的命令。
- `recall`：搜本任务账本（含被压缩的部分）、按序号取原文；裁剪占位符带序号；摘要末尾说明原文在账本里。命令行也加上了。
- 测试：`tests/test_jobs.py`（9 项）。

**实现时发现并修掉的问题**：

1. **命令在启动后 3 秒内就结束了**：结束通知会插在这次工具调用的中间（结果还没记，通知先到），而且结果已经直接返回给模型了，再通知就重复了。改成：启动阶段结束的不另外通知。
2. **Agent 主动结束命令时**，回收线程可能先看到进程退出，把它记成“失败，退出码 -15”。改成：先标记“正在被结束”，谁先看到都记成“被结束”。
3. **重启时核对“还是不是我们启动的那个进程”**：原计划比命令行，但 `bash -c "sleep 30"` 会直接把自己换成 `sleep`，命令行对不上，残留的进程永远清不掉。改成比进程启动时间（`ps -o lstart`），再加上“进程组组长是它自己”。

**真实验证（OpenRouter）**：

- 后台命令：`sleep 8; echo 数据导出完成，共 1234 行`。放行后台启动，模型先回答“已在后台启动”，这一轮结束；8 秒后收到通知，任务被叫醒，模型回答“数据导出完成，共 1234 行”。
- 取消：放行 `sleep 60` 后 3 秒取消，立刻停下，状态“已取消”。
