# ask_user 实现计划

> **给执行的 Agent：** 用 subagent-driven-development（推荐）或 executing-plans 逐个任务执行。步骤用 `- [ ]` 勾选跟踪。

**Goal:** Weaver 能在任务中途问用户一个问题、等回答再接着做；Keygent 弹出问题卡，全程键盘操作。

**Architecture:** `ask_user` 是一个权限规则一律“等人”的工具，复用审批的等待机制（kind=`question`）；有结论后内核把答案作为非错误的工具结果交回模型。daemon 渲染新 kind、翻译 answer / skip；Keygent 加问题卡、自动弹出、输入锁。

**Tech Stack:** Python 3（只用标准库，unittest + pytest 运行）；Swift / SwiftUI（Keygent，xcodegen + xcodebuild）。

**Spec:** `design/ask-user.md`

## Global Constraints

- 工具名 `ask_user`，参数 `question: str`（必填、非空）、`options: [str]`（可选；给就 2~4 个）。
- 等待 `kind: "question"`，`choices: ["answer", "skip"]`，多一个字段 `options`（没有就是 `[]`）。
- 回答：`{"decision": "answer", "note": "<非空>"}` → 账本值 `{"allow": true, "answer": note}`；`{"decision": "skip"}` → `{"allow": true, "skip": true}`。
- 交回模型的文字，逐字：`用户回答：<答案>`；`用户这次没回答。按你自己的判断继续，并在结论里写明你做了什么假设。`
- 只给主 Agent，子 Agent 不给。`--yes`（`PermissionPolicy.yes`）时不等人，直接返回 skip 的文字。
- ask_user 的判断放在所有自动放行规则之前。
- 步骤标题 `问你：<问题>`；有结论后 `out` 是 `你答：<答案>` 或 `你让它自己定`；任务 `now` 是 `问你：<问题>`。
- 胶囊文字：question「<任务名> · 问你」，其余「<任务名> · 等你放行」。
- Keygent 自动弹出后输入锁 0.5 秒；自动弹出时记下原来的 App，回答 / ⌘↵ / esc 后激活它。
- 测试命令：`python3 -m pytest tests -q`（基线 334 passed, 13 skipped）。
- Keygent 构建：`cd Keygent && xcodegen generate && xcodebuild -project Keygent.xcodeproj -scheme Keygent -derivedDataPath build/DD build`。weaverd 由 launchd 管，⌘R 不重启它，靠代码指纹自动重启。

## Review Focus

1. **中文输入法组字时按 ↵**：应当只确认候选词，不能发送回答；输入锁期间不允许开始组字，锁结束后输入法正常工作。→ Task 7 Step 6 第 5 条。
2. **同一条回复里 ask_user 和别的工具一起调用**（比如 ask_user + read_file）：read_file 照常执行，问题照常等，答完后模型同时看到两个结果。→ Task 2 测试 `test_question_alongside_other_call`。
3. **一条回复里两个 ask_user**：两件等待都出现；Keygent 一次弹一个，答完第一个弹第二个。→ Task 2 测试 `test_two_questions_in_one_reply`；Task 7 Step 6 第 4 条。
4. **daemon 重启时有问题在等**：重启后等待还在、照样能回答。→ Task 3 测试 `test_question_survives_reload`。
5. **⌘数字 超出选项个数**（只有 2 个选项按 ⌘3）：不做任何事，不发请求。→ Task 6 Step 5 第 3 条。
