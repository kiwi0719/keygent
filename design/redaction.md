# Weaver 脱敏设计

草案 v1 · 2026-10-01

## 一、要解决什么问题

Agent 会读文件、跑命令，结果原样进账本、显示在终端、发给模型服务商。只要碰到一个含密钥的文件（`.env`、配置文件、`env` 命令的输出、报错日志），密钥就会：

1. 发到模型服务商（离开本机）；
2. 写进 `.weaver/` 下的账本、完整输出文件（留在磁盘上）；
3. 可能被模型复述、写进别的文件。

main.md 第 21 课的结论：**脱敏要分几处做**——发给模型前、写日志时、导出时。

## 二、Claude Code 的做法（照着做）

`claude-code-best/src/services/teamMemorySync/secretScanner.ts`（团队记忆上传前的扫描）：

- **规则来自 gitleaks**（MIT 许可），但**只挑高置信度的**：带明显前缀的密钥（`AKIA…`、`ghp_…`、`sk-ant-api03-…`、`xoxb-…`、`-----BEGIN … PRIVATE KEY-----`……），误报率接近零。
- **通用的关键字规则一律不要**（`password=…`、`token: …` 这类）：误报太多，会把正常内容搞坏。
- **只返回“哪条规则命中了”，不记录、不显示密钥本身。**
- 在**数据离开本机之前**扫描。
- 调试输出里的脱敏（`bridge/debugUtils.ts`）**保留首 8 位和末 4 位**，方便人认出是哪个密钥；太短的直接整个换掉。
- 子进程环境变量去掉密钥（`utils/subprocessEnv.ts`）——我们的 bash 已经这样做了（write-tools.md）。

## 三、我们的做法

### 1. 两类识别

| 类型 | 做法 | 为什么 |
|---|---|---|
| **规则** | 移植 Claude Code 的 36 条 gitleaks 精选规则：AWS、GCP、Azure、DigitalOcean、Anthropic、OpenAI、HuggingFace、GitHub（5 种）、GitLab、Slack、Twilio、SendGrid、npm、PyPI、Databricks、Terraform、Pulumi、Postman、Grafana、Sentry、Stripe、Shopify、私钥 | 高置信度，几乎不误报 |
| **已知的值** | 本进程环境变量里，名字含 `KEY` / `TOKEN` / `SECRET` / `PASSWORD` / `CREDENTIAL`、值长度 ≥ 12 的，按值原文替换 | Claude Code 的规则**没有 OpenRouter 的 key**（`sk-or-v1-…`），而这正是我们自己在用的；`.env` 读进来的 key 都在环境变量里，按值精确匹配最可靠（OpenHands SDK 的 `secret_registry` 也是这个思路） |

### 2. 替换成什么

```
[已脱敏 GitHub PAT: ghp_aBcD…wXyZ]      长度 ≥ 16：保留首 8 位、末 4 位
[已脱敏 环境变量 OPENROUTER_API_KEY]     已知的值：写变量名，不留任何字符
[已脱敏 Private Key]                    私钥、太短的值：整个换掉
```

有脱敏时，在工具结果末尾附一句：“[输出里有 2 处疑似密钥已脱敏：GitHub PAT、AWS Access Token。需要用到时请让用户自己处理，不要尝试还原。]”，让模型知道发生了什么。

### 3. 在哪里脱敏

**在工具结果进入账本的那一刻**（执行者记 `ActionCompleted` 之前）。一处做了，下游全干净：

| 下游 | 效果 |
|---|---|
| 发给模型 | 看不到密钥 |
| 账本、终端显示 | 磁盘和屏幕上都没有 |
| bash 的完整输出文件（`.weaver/outputs/`） | 存之前也脱敏 |
| 压缩摘要、子 Agent 汇报 | 来源已经干净 |
| 模型的报错信息（适配器抛出的 HTTP 错误正文） | 记进账本前同样过一遍 |

**用户自己输入的话不脱敏**：用户有时就是要把 token 交给它用（“用这个 token 调一下接口”），脱了反而坏事。这是用户有意识的选择。

### 4. 防止把占位符写回文件

模型看到的是占位符。如果它照着读到的内容整体重写一个配置文件，就会把真密钥冲成 `[已脱敏 …]`。所以：

- `write_file`、`edit_file` 的内容里出现 `[已脱敏 ` 就拒绝，提示“内容里有脱敏占位符，写回去会毁掉原来的密钥。只改需要改的部分（用 edit_file 且不要包含占位符那一行），或者请用户自己改”。
- `edit_file` 的 `old_string` 里带占位符本来就匹配不上原文，会报“没找到”，天然安全。

### 5. 和已有模块统一

- 记忆写入前的密钥检查（memory.md）先用同一套规则 + 已知的值，**再保留原来几条更严的兜底**（通用 `sk-…`、单独的私钥开头、`token = …` 这类关键字赋值）。和工具结果不同：记忆每次会话都会读进来，误拒的代价只是“换个写法再存”，漏掉的代价是密钥长期留在上下文里，所以这里宁严勿松。注入检查不变。
- bash 子进程去掉密钥环境变量：已有，不变。

## 四、取舍

- **不做通用关键字规则**：`password = hunter2` 这类不会被脱敏。宁可漏掉一些，也不把正常内容（如“token 预算设成 200k”）搞坏。这是 Claude Code 的明确选择。
- **账本里不留原文**：脱敏发生在进账本之前，所以事后也找不回被脱敏的值。这是有意的：本机磁盘上也不该留。
- **不影响缓存**：脱敏是确定的（同样的输入得到同样的输出），而且发生在进账本前，投影出来的前缀照样稳定。

## 五、测试

1. 每条规则一个真实格式的样例能命中；首 8 末 4 的格式；太短 / 私钥整个换掉。
2. 不误报：普通代码、UUID、git 提交哈希、base64 图片片段、“token 预算 200k”。
3. 已知的值：环境变量里的 key 原文出现在输出里被换成变量名；太短的值、名字不像密钥的变量不处理。
4. 执行者：工具结果进账本前已脱敏；附提示；终端和发给模型的内容一致；用户输入不脱敏。
5. bash 的完整输出文件里没有密钥。
6. 写回保护：write_file / edit_file 内容带占位符被拒绝。
7. 记忆：用统一规则拒绝含密钥的内容。
8. 真实验证：工作目录放一个含（假的）GitHub token 和真实 OpenRouter key 引用的文件，让它读出来，确认模型和账本里都看不到原文。
